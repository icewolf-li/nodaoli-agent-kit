# Git 工作方式

- 开始前检查分支、工作区差异与远程；不能把用户已有修改当作本次生成的内容。
- 提交前检查 diff 和暂存范围，排除临时文件、备份、凭据及无关改动。
- 不擅自执行 reset --hard、clean、强推或重写他人提交；遇到冲突保留双方意图并验证结果。
- 新任务需要独立分支时使用 `codex/` 前缀，用户指定名称时按用户要求。
- 提交说明写清变更目的，PR 说明描述最终行为与验证情况。
- 用户要求初始化时可以创建本地仓库；提交、推送、建远程、合并或发布按本次任务的授权范围执行。
- 不把管理仓库连同 `.git/` 克隆到业务项目里；安装器只复制项目需要的规则与精选 Skills。
- 业务项目建议提交 Agent 入口、规则、Skills 与适合共享的项目记忆，使换电脑后仍能使用。
